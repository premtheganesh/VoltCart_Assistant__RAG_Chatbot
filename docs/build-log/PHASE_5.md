# Phase 5 — Agent v1 (RAG answers)

**Goal:** a working chatbot: understands the request, remembers the conversation, answers from the documents with citations, says "I don't know" when it should, and records every step in Langfuse.

```
START ─► router ─┬─ product_info / recommendation ─► retrieve ─► answer (cited) ─► END
 (small LLM:     ├─ smalltalk ─► short friendly reply ─► END
  route +        ├─ off_topic ─► polite refusal ─► END
  rewrite)       ├─ order ─────► self-service pointer ─► END     (verified lookup: Phase 6)
                 └─ handoff ───► support contacts ─► END         (tickets: Phase 6)
memory: Postgres checkpointer, one thread per conversation      traces: Langfuse
```

## What was built and why

| File | What it does | Why |
|---|---|---|
| `app/llm/chat.py` | `get_chat_model("main" / "small")` from `.env` (`provider:model`) | Swap models without code changes. Needed on day one: Groq retired the Llama models we planned for |
| `app/graph/state.py` | Conversation state: messages + this turn's route, search query, sources, gate, citations | LangGraph saves it after every step; plain data so it can be stored in Postgres |
| `app/graph/prompts.py` | Router, answer and small-talk prompts + fixed replies | One reviewable place; fixed replies for refusals and "I don't know" cost no LLM call and can't go wrong |
| `app/graph/builder.py` | The graph, citation extraction, citation normalising | Dependencies are injected, so tests run with fake models |
| `app/graph/agent.py` | Wires real models, hybrid retrieval, Postgres memory, Langfuse; router retry + keyword fallback | `agent.ask(thread_id, message)` is what the API will call in Phase 8 |
| `app/observability.py` | Langfuse callback (optional, off without keys) | See every step, prompt, output and timing of a turn |
| `scripts/chat.py` (`make chat`) | Terminal chat with `/new`, `/debug`, `/quit` | Talk to the bot before there's a UI |
| `scripts/eval_routing.py` (`make eval-routing`) | Router accuracy on all 122 golden questions + follow-up rewrites | PRD target ≥ 0.90; cached, retries on rate limits, never scores a failure |

## Key choices

- **One small-LLM call does routing and query rewriting** ("how much is it?" → "Nova X price"). Halves latency and free-tier usage versus two calls.
- **Router → fast model, answers → strong model.** Small model with thinking off and output capped at 512 tokens: ~0.5–1 s per route.
- **The relevance gate short-circuits the LLM.** If retrieval finds nothing relevant, the reply is a fixed "I couldn't find that... connect you with support?": the model never gets a chance to guess.
- **Citations are normalised in code.** gpt-oss writes `【1†L1-L7】`; we convert to `[1]`, keep only numbers that match a source, and return the cited sources (title, heading, URL, page) for the UI.
- **Router never breaks the chat:** one retry, then keyword fallback ("real person" → handoff, "VC-10003" → order). Evals call it with `fallback=False`, so a rate-limit failure is never scored as the model's answer.
- **Memory:** Postgres checkpointer keyed by thread id; the LLM sees the last 10 messages. Alembic now ignores LangGraph's 4 checkpoint tables (without this, the next autogenerated migration would have dropped them).

## Results

- **Routing accuracy 0.98** on 122 golden questions (target 0.90), router `qwen/qwen3.8-27b`. All 9 follow-ups rewritten correctly ("is there something cheaper that still works for that?" → "cheaper VoltBook laptop suitable for 4K video editing").
- Known miss: "turbo mode is greyed out on my gaming laptop" → off_topic. A keyword safety net was measured and rejected (scores of on- and off-topic messages overlap); revisit in Phase 7/11.
- `make test-all`: 1419 passed (22 agent tests with fake models, incl. memory surviving a restart in Postgres). Lint clean.

## Lessons from this phase

- **Free providers change and run out.** Llama models retired; gpt-oss-20b's daily token budget was used up by ~490 router calls. Limits are per model, so switching models restored service. Phase 12 adds an automatic fallback provider.
- **Don't teach to the test.** A prompt example identical to a golden question ("best Dell laptop") inflated accuracy; replaced with a different example before trusting the number.
- **Evals must not cache failures.** A rate-limited run once cached fallback answers and showed a fake drop to 0.82.
- **Stale index.** The bot quoted the test-only 45-day returns policy: the file was restored but not re-ingested. An index is only as fresh as its last ingest.

## Concepts to know

- **LangGraph:** a state machine. Nodes are functions that read the state and return updates; conditional edges choose the next node; a checkpointer saves state per thread.
- **Structured output:** the model must return JSON matching a schema (`route`, `search_query`), so code can branch on it.
- **Query rewriting:** follow-ups are rewritten into standalone search queries before retrieval.
- **Reasoning models:** gpt-oss and Qwen "think" before answering; hidden thinking tokens cost time and quota, so cap them for simple tasks.
- **Trace:** a record of one request: each step's input, output, model, tokens and latency.
